# ใบลงเวลา → AI อ่าน → ชีต (ผ่านบอท LINE หรืออัปรูปในเว็บ)

## ออกแบบใบลงเวลาให้ AI อ่านง่าย (บทเรียนจากของจริง)
- **คอลัมน์ให้น้อยที่สุด**: วันที่ | เวลาเข้า | เวลาออก | (รวม — เขียนอิสระ AI ไม่อ่าน)
  ใบเดิม 7 คอลัมน์ (พัก/ชม.ปกติ/OT/ลายเซ็น) ตัดทิ้งแล้ว — ระบบคำนวณเองจากเข้า-ออก
- **ห้ามให้ AI อ่านช่อง OT/พัก/ชม.ปกติ** — เลขลายมือ "8:0" ถูกอ่านเป็น 80; ส่งค่าว่างมาเสมอแล้วให้ `calcRowHours_` คิด
- หัวใบมีรหัสฟอร์ม/โลโก้ที่แยกบริษัทได้ (เช่น PAY-TS กับรหัสของอีกบริษัท) → บอทตัวเดียวส่งเข้าเว็บของบริษัทที่ถูกต้อง
  ถ้าไม่ได้ตั้ง URL ของบริษัทนั้น = **ปฏิเสธ** ห้ามถอยไปส่งเข้าบริษัทอื่น
- 1 ใบ ≤ 16 แถว · พิมพ์ชื่อ/รหัส/งวดลงใบให้ล่วงหน้าได้ (ลดการอ่านผิด)
- ผลทดสอบจริง Gemini กับลายมือ: 6/6, 11/11, 13/13 แถว

## เรียก Gemini จาก Apps Script (`TimesheetOcr.gs`)
- คีย์เก็บใน Script Properties `GEMINI_API_KEY` (หลายคีย์คั่น `,` — ฟรีก่อนแล้วเสียเงิน) · ส่งทาง header `x-goog-api-key` ไม่ใส่ใน URL
  · ล้างคีย์ออกจากทุกข้อความ error/log
- `generationConfig`: `responseMimeType: application/json`, `temperature: 0`, `responseSchema`, thinking (2.5 = `thinkingBudget`, 3.x = `thinkingLevel`)
- ลำดับรุ่น: `GEMINI_MODEL` → `GEMINI_FALLBACK_MODEL` → `gemini-3.5-flash` → `gemini-2.5-flash` (2.5 คีย์ใหม่เรียกไม่ได้ตั้งแต่ ต.ค. 69)
- ลองรุ่นตามลำดับ · **400** (รุ่นไม่รับ schema/thinking) → ถอดทีละชั้นแล้วลองใหม่ · **429** → คีย์ถัดไป · 401/403 → หยุด
  · ทุกคีย์ 429 → บอกผู้ใช้ "โควต้า AI ของวันนี้เต็มแล้ว — ลองใหม่ภายหลัง หรือกรอกเอง"
  · ทุกข้อความ error ที่ส่งถึงหน้าเว็บ **แนบ `error.message` ของ Google (ล้างคีย์แล้ว ≤160 ตัว)** — 403 "denied access" แยกข้อความ "Google ระงับโปรเจกต์ที่ออกคีย์นี้"
- ปุ่ม "ทดสอบคีย์ AI" (ตั้งค่าระบบ) → `apiTsOcrReady(pin, true)` → `tsocrPing_()` ส่งข้อความสั้น 1 ครั้งตามลำดับรุ่นเดียวกัน ·
  `apiTsOcrReady(pin)` แบบเดิม (ไม่ส่ง true) ยังแค่ดูว่ามีคีย์ ไม่ยิงเน็ต
- อ่าน 1 รอบพอ (ไม่โหวตหลายรอบ) — ประหยัดโควต้าและกันชนเพดาน 6 นาทีของ Apps Script
- prompt ให้ส่ง `is_timesheet` (รูปไม่ใช่ใบลงเวลา → ตอบกลับชัดๆ), `raw_*` ข้อความดิบ, `unreadable` ต่อแถว
- แปลงวันที่: เลขไทย→อารบิก, พ.ศ.→ค.ศ., ปี 2 หลัก, ใช้ช่วงงวดช่วยเดาเดือน/ปีที่ขาด · วันที่ > วันนี้ → ธง `future`

## รับจากบอท — `doPost`
payload: `{ lineUserId, displayName, summary, receivedAt, image?, contentType?, rows:[{employee_id, employee_name, work_date, check_in, check_out}] }`
- เขียนทุกแถวเป็น `status = รอตรวจสอบ` + ลิงก์รูปต้นฉบับเดียวกันทุกแถว + log ใน Import_Log
- `body.action` (เช่นขอสลิป) = คำขอที่ให้ข้อมูลออก → **ต้องมี `secret`** เทียบกับ Script Property `BOT_SECRET`
  (`botAuthOk_` เทียบแบบเวลาคงที่, ยังไม่ตั้ง = ปฏิเสธ)
- `setupBotSecret()` รันในเอดิเตอร์ → ค่าอยู่ใน Execution log → ตั้งเป็น env ฝั่งบอท · **ห้าม return ค่า** (เว็บ anonymous เรียกได้)

## พนักงานขอสลิปตัวเองผ่าน LINE
- **ห้ามรับ employee_id จากภายนอก** — ตัวตนมาจาก `line_user_id` ที่ LINE เซ็นรับรองแล้วเท่านั้น
- จับคู่ LINE id → พนักงาน จากแถว Attendance ที่เจ้าตัวส่งเองผ่านบอท (ไล่จากแถวใหม่สุด)
- ส่งเฉพาะสลิปที่ออกแล้วใน `05_Payslips`

## หน้าเว็บอัปรูปใบลงเวลา
- `apiOcrTimesheet`: รหัสพนักงานต้องมีในทะเบียน · เช็ค magic bytes JPEG/PNG จริง · จำกัดขนาด · **เก็บรูปลง 01_Inbox ก่อนเรียก AI เสมอ** (AI ล้มก็ยังมีรูปให้กรอกเอง)
  · ส่งกลับแค่ `file_id` ไม่ส่ง URL Drive
- `apiSaveTimesheetRows`: ผู้ใช้ตรวจแก้ในตารางก่อนกดบันทึก · `file_id` ต้องอยู่ใน `01_Inbox` จริง (`inFolder_`) · เขียนผ่านฟังก์ชันเดียวกับ doPost
- ย่อรูปฝั่งเบราว์เซอร์ก่อนส่ง (~0.3–1 MB)

## ทดสอบโดยไม่ทิ้งขยะ
- ยิง doPost **ไม่ใส่ `image`** → ไม่สร้างไฟล์ Drive เหลือแถวในชีตให้ลบ
- ใช้ `lineUserId` ขึ้นต้น `TEST_BOT_` (LINE id จริงขึ้นต้น `U`) แล้วมี api ลบเฉพาะแถว/ไฟล์ทดสอบนั้น
- `curl` ยิง /exec ตรงไม่ได้ (302 → 411 Length Required) → ใช้ Node `fetch(url, {method:'POST', body, redirect:'follow'})`
  และอย่าตั้งชื่อตัวแปร `URL` (ทับ constructor)
